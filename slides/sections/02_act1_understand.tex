\begin{frame}{The filesystem is the source of truth}
  \begin{center}
    New to research software? Start here --- everything else in this talk builds on this one habit.
  \end{center}
  \vspace{-0.75cm}
  \begin{columns}[t]
    \begin{column}{0.46\textwidth}
      \begin{center}\textbf{A conversation}\end{center}
      \begin{itemize}\small
        \item not versioned
        \item not shared with collaborators
        \item not searchable next year
        \item gone when the session ends
      \end{itemize}
    \end{column}
    \begin{column}{0.46\textwidth}
      \begin{center}\textbf{A repository}\end{center}
      \begin{itemize}\small
        \item versioned
        \item shared by construction
        \item searchable history
        \item outlives everyone involved
      \end{itemize}
    \end{column}
  \end{columns}
  \vspace{0.6em}
  \begin{center}\small
    Most important advice for today, whether you write code or just run experiments --- use \textbf{version control}. Something stopped working? It becomes a time machine. \\
  \vspace{0.7em}
    Getting started is easy: create a GitHub account, apply for education free upgrades\textsuperscript{1}, watch a tutorial\textsuperscript{2}, install GitHub Desktop\textsuperscript{3}.
  \end{center}
  \vspace{0.6em}
  \begin{center}
    {\tiny \textsuperscript{1}~\texttt{github.com/education} \quad \textsuperscript{2}~\texttt{youtu.be/a9u2yZvsqHA} \quad \textsuperscript{3}~\texttt{desktop.github.com/download}}
  \end{center}
\end{frame}

\begin{frame}{An agent can touch your repository --- a chatbot can't}
  \vfill
  \begin{center}
  \begin{tikzpicture}[font=\normalsize, node distance=1.3cm]
    \node[draw=NDBlue, rounded corners=2pt, minimum width=3.1cm, minimum height=1.6cm, align=center]
      (a) {\textbf{LLM}\\\small the model};
    \node[draw=NDBlue, rounded corners=2pt, minimum width=3.9cm, minimum height=1.6cm, align=center, right=of a]
      (b) {\textbf{Chatbot}\\\small LLM + a chat window\\\small text in, text out};
    \node[draw=NDGold, rounded corners=2pt, minimum width=4.2cm, minimum height=1.6cm, align=center, right=of b, fill=CodeBg]
      (c) {\textbf{Agent}\\\small LLM + tools\\\small reads, writes, and executes your files};
    \draw[-{Stealth[length=6pt]}, thick] (a) -- (b);
    \draw[-{Stealth[length=6pt]}, thick] (b) -- (c);
  \end{tikzpicture}
  \end{center}
  \vspace{0.6em}
  \begin{center}
    A chatbot only has the conversation and the files you share (e.g., uploading/attaching a PDF).
  \end{center}
  \vspace{0.6em}
  \begin{center}
    An agent can \textbf{interact with your repository}: follow instructions with \texttt{CLAUDE.md} or \texttt{AGENTS.md}, edit the code, debug errors, run the tests, maintain logs, search history, and commit.
  \end{center}
  \vfill
\end{frame}

\begin{frame}{Task 2 --- a chat history can't hold any of these three}
  \vfill
  \begin{center}
    Every new chat starts from zero. Three things a project needs that a conversation can't hold on its own:
  \end{center}
  \vspace{0.5em}
  \begin{columns}[t]
    \begin{column}{0.31\textwidth}
      {\color{NDBlue}\textbf{Persistent}}\\[0.4em]
      Your data and results don't change between sessions. \\[0.4em] 
      {\footnotesize A changing number could be a finding or a bug.} \\[0.7em]
    \end{column}
    \begin{column}{0.31\textwidth}
      {\color{NDBlue}\textbf{Authoritative}}\\[0.4em]
      The actual code and data. \\[0.4em] {\footnotesize Point an agent at the real files under (version control!); never describe them from memory.}\\[0.7em]
    \end{column}
    \begin{column}{0.31\textwidth}
      {\color{NDBlue}\textbf{Task}}\\[0.4em]
      What you're working on right now, defined fresh each session.\\[0.4em]
      {\footnotesize For complex tasks, you may find it helpful to have a coordinator agent (e.g., Opus/Fable, Terra/Sol) draft and save prompts that are sent to workers, then save the text summary created by the worker(s).} \\[0.7em]
    \end{column}
  \end{columns}
  \vfill
\end{frame}

\begin{frame}[fragile]{Task 2 --- write down what you'd otherwise re-explain every session}
  \ndlogonote{\scriptsize\href{https://github.com/dowlinglab/claude-for-researchers/blob/main/resources/templates/research_log.md}{\texttt{resources/templates/research\_log.md}}}
  \vfill
  \begin{columns}[c]
    \begin{column}{0.62\textwidth}
      \begin{lstlisting}[basicstyle=\ttfamily\scriptsize]
# Project

Membrane transport parameter estimation.

## Where things are
  src/       the model
  results/   written by scripts; never by hand
  configs/   every run is a config file
## How to run
  conda activate diafiltration
  python -m pytest -m "not slow"
## Conventions
  Results are deterministic. A change in a
  number is a finding, not noise.
## Current state
  Working on: replicate weighting
  Resume at: notes/log.md, 2026-08-14
      \end{lstlisting}
    \end{column}
    \begin{column}{0.34\textwidth}
      \small
      Name it neutrally, such as \texttt{START\_HERE.md}. \\[0.6em] Then, add tool-specific files such as \texttt{CLAUDE.md} (Claude Code) or \texttt{AGENTS.md} (Codex, Cursor, Gemini CLI, and 20+ other tools) --- both become three-line pointers to your neutrally named file.\\[0.6em]
      {\scriptsize Review it like any doc: stale instructions mislead. Longer-running notes belong in a separate log.}
    \end{column}
  \end{columns}
  \vspace{1.8cm plus 1fill}
\end{frame}

  \vspace{0.5em}
  \begin{center}
  \begin{enumerate}\small\setlength\itemsep{0.25em}
    \item Search a second, adjacent field on purpose --- not just your own topic
    \item Download papers in small batches, not one large dump
    \item Process each batch, with a checkpoint before the next one starts
    \item Judge relevance to your project, don't just summarize the abstract
    \item Recheck every quantitative claim against the source, in a second pass
  \end{enumerate}
  \end{center}
  \vspace{0.4em}
  \begin{center}
    {\scriptsize The corpus arrives to pressure-test an idea already forming, not to generate one.}
  \end{center}
