## Session structure

The seminar is **two parts, two weeks apart**, each 1 hour 45 minutes (3:30–5:15 PM, McCourtney Hall B01):

| | Date | Presentation | Hands-on activity |
|---|---|---|---|
| **Part 1** | Monday, September 28, 2026 | Original slides 1–26 — workspace, instructions, reproducible baseline | Activity 1: instructions and baseline |
| **Part 2** | Monday, October 12, 2026 | Original slides 27–54 — literature, audit, draft, and trust | Resume extraction, then audit selected report claims |

Between sessions, participants experiment on their own research. Activity 1
Phase 3 is next-session work. Additional literature sources are optional for
the full writing workflow; the in-room audit uses the shared fallback report.

The split is implemented with shared slide sources: **27 frames in Part 1,
31 in Part 2**, including session titles and closings. Each session allocates
**35 minutes presentation, 10 Q&A, 45 hands-on, 15 regroup**. See the
[session guide](resources/workshops/cstr/activities/session_guide.md) for the
bounded exercises and [open questions](notes/open_questions.md) for pilot work.

## Talk structure

| Section | Purpose |
|---|---|
| Prologue: Tinker | Start with a concrete project, state the thesis, and introduce the companion repository |
| Act I: Understand | Task 1: configure Git, the environment, and agent instructions; explore inherited work |
| Act II: Build | Task 2: package published code; Task 3: create a literature-grounded report or proposal |
| Act III: Challenge | Task 4: audit a manuscript; Task 5: draft one from accumulated evidence; Task 6: modernize a course |
| Epilogue: Trust | Address policy, responsibility, recurring habits, hobbies, and next steps |

Tasks 1–6 form the research workflow. The hobbies are an unnumbered extension. The talk's central message is that AI becomes more useful when it works inside a deliberate, reproducible, and auditable workflow whose state lives in files and Git rather than in one chat session.
